## 二、P0 优先级需求

### 2.1 Evidence Ledger（主张-证据台账）

**PRD 原文（FR-DEEPREAD-4）**：
> - 自动从总结/结论段生成初稿（可编辑）
> - 每条 claim 绑定证据锚点与强度评级

**页面交互说明**：
> - Claim 列表（每条可展开：证据锚点 + 不确定性）
> - `Promote to EvidenceCard`（固化成卡片）
> - `Add claim`：用户自己写 claim，系统建议该去找哪些段落/图表支持

#### 功能需求

1. **位置**：Main 底部，可折叠抽屉
2. **数据结构**：
```typescript
interface Claim {
  id: string;
  text: string;                    // 主张文本
  evidence_anchors: string[];      // 证据锚点ID列表
  strength: 'strong' | 'medium' | 'weak';  // 证据强度
  uncertainty: 'from_text' | 'inferred' | 'needs_verify';
  alternative_explanations?: string[];  // 替代解释
  risks?: string[];               // 风险点
}
```

3. **核心交互**：
   - 一键从论文结论段生成初始 Claim 列表
   - 点击 Claim 展开：显示证据锚点（可点击跳转）、强度评级、替代解释
   - 编辑 Claim 文本
   - 添加/删除证据锚点
   - 调整证据强度
   - "生成 EvidenceCard" 按钮
   - "添加新 Claim" 按钮

4. **后端 API**：
   - `POST /api/v1/papers/{paper_id}/evidence-ledger/generate` - 自动生成
   - `GET /api/v1/papers/{paper_id}/evidence-ledger` - 获取
   - `PUT /api/v1/papers/{paper_id}/evidence-ledger` - 更新
   - `POST /api/v1/papers/{paper_id}/evidence-ledger/to-card` - 转为卡片

5. **UI 组件**：
   - `EvidenceLedger` - 主容器（可折叠抽屉）
   - `ClaimItem` - 单条主张
   - `EvidenceAnchorChip` - 证据锚点标签
   - `StrengthBadge` - 强度徽章

### 2.2 结构化视图内嵌块

**PRD 原文（FR-DEEPREAD-1）**：
> Structured View（章节摘要、方法块、实验块）

**线框图描述**：
> - 当前章节摘要（严格版）
> - 方法流程图（可折叠）
> - 实验设置复原块（数据/指标/baseline）

**页面交互说明 4.3**：
> - "方法复原块"可折叠：展开后出现：输入/输出/假设/流程/复杂度/伪代码
> - "实验设置复原块"按钮：`Extract to Checklist`

#### 功能需求

1. **当前问题**：方法流程和实验设置使用模态框展示，不符合文档设计

2. **改进方案**：
   - 将模态框改为内嵌可折叠块
   - 放在结构化视图底部（快速提取区域下方）
   - 或嵌入到对应章节下方

3. **UI 设计**：
```
┌─────────────────────────────────┐
│ 结构化视图                        │
├─────────────────────────────────┤
│ ▼ Abstract                      │
│ ▼ Introduction                  │
│ ▼ Method                        │
│   ├─ 章节摘要（自动生成）          │
│   └─ [方法流程块] ← 可折叠         │
│       ├─ 方法名称                 │
│       ├─ 步骤流程                 │
│       ├─ 创新点                   │
│       └─ [提取到清单]             │
│ ▼ Experiments                   │
│   ├─ 章节摘要（自动生成）          │
│   └─ [实验设置块] ← 可折叠         │
│       ├─ 数据集                   │
│       ├─ 指标                     │
│       ├─ 超参数                   │
│       └─ [提取到清单]             │
│ ▼ Results                       │
│ ▼ Conclusion                    │
├─────────────────────────────────┤
│ 快速提取                          │
│ [方法流程] [实验设置]              │
└─────────────────────────────────┘
```

4. **章节摘要功能**：
   - 每个章节可展开显示 AI 生成的摘要
   - 支持"严格版"和"通俗版"切换
   - 后端需要 `POST /api/v1/enhance/section-summary/{anchor_id}`

5. **Extract to Checklist**：
   - 在方法块/实验块中增加"提取到清单"按钮
   - 点击后将关键信息批量添加到 ReproChecklist

## 三、P1 优先级需求

### 3.1 Quote Snippet（引用骨架生成）

**PRD 原文（FR-DEEPREAD-3）**：
> Quote snippet（生成"可改写引用骨架"，不直接复制原句）

#### 功能需求

1. **触发方式**：Selection Toolbar 增加"引用骨架"按钮
2. **功能**：
   - 将选中文本转换为学术写作可用的引用骨架
   - 不直接复制原句，而是生成可改写的表述
   - 自动附带引用信息（作者、年份）
3. **输出格式**：
```
[引用骨架]
根据 Author et al. (2024) 的研究，[核心观点改写]。
该工作提出了 [方法/发现概述]，在 [应用场景] 中取得了 [效果描述]。

[原文参考]
"原始文本..."（第X页）

[引用格式]
@article{...}
```

4. **后端 API**：
   - `POST /api/v1/enhance/quote-snippet`
   - 请求：`{ paper_id, selected_text, anchor_id }`
   - 返回：`{ skeleton, citation, original_ref }`

5. **UI**：
   - Selection Toolbar 增加 `<Quote />` 图标按钮
   - 点击后在右侧 Panel 显示生成结果
   - 支持复制到剪贴板

### 3.2 Chat Tab（对话协作）

**页面交互说明**：
> - Chat（围绕选中文本对话，带引用锚点）
> - 推荐动作按钮：加入清单 / 生成卡片 / 提一个审稿问题

**页面和组件级信息架构**：
> - `ContextDock`（当前对话引用了哪些段落/图表/卡片）
> - `ModeSwitch`（组会模式/写作模式/复现模式/方案设计模式）
> - `ActionSuggestions`

#### 功能需求

1. **位置**：右侧 Panel 增加 Chat Tab

2. **核心功能**：
   - 基于当前论文的上下文对话
   - 自动携带选中的锚点作为上下文
   - 支持模式切换：
     - 组会模式：追问式，帮助准备讲稿
     - 写作模式：输出段落骨架
     - 复现模式：询问缺失项，生成实验计划
     - 方案设计模式：给多方案并标注风险

3. **交互设计**：
   - 从 PDF 选中文本 → 自动附加到 Chat 上下文
   - 每条回复下方显示动作按钮：
     - "生成 EvidenceCard"
     - "加入复现清单"
     - "转为审稿问题"
   - Context Dock 显示当前引用的锚点

4. **UI 组件**：
   - `ChatPanel` - 主容器
   - `ChatMessage` - 消息气泡（带锚点引用标签）
   - `ChatComposer` - 输入框 + 附加上下文按钮
   - `ModeSwitch` - 模式切换器
   - `ContextDock` - 上下文锚点展示
   - `ActionSuggestions` - 动作建议按钮

5. **后端 API**：
   - `POST /api/v1/chat/{paper_id}` - 发送消息
   - `GET /api/v1/chat/{paper_id}/history` - 获取历史

### 3.3 生成 PaperCard

**页面交互说明 4.4**：
> `Convert to PaperCard`（完成精读后）
> - 系统根据已有卡片合成 PaperCard（用户可改）

#### 功能需求

1. **触发时机**：
   - 精读完成时（进度 100%）自动提示
   - 工具栏增加"生成 PaperCard"按钮

2. **生成逻辑**：
   - 基于已有的 EvidenceCard、MethodCard 合成
   - 结合 SkimCard 信息
   - 如果没有足够卡片，直接从论文内容生成

3. **PaperCard 内容**：
```typescript
interface PaperCard {
  one_line_summary: string;     // 一句话贡献
  contributions: string[];       // 3个要点
  limitations: string[];         // 2个局限
  applicable_scope: string;      // 适用边界
  repro_risk: string;           // 可复现风险
}
```

4. **后端 API**：
   - `POST /api/v1/cards/paper/{paper_id}/generate-paper-card`
